# Multiple spec consolidation opportunities for better organization

## Issue Description
Several groups of specifications address overlapping concerns and could be consolidated to reduce complexity and improve maintainability.

## Consolidation Opportunities

### 1. Parser and CLI Integration
**Affected specs:** `spec-parser`, `spekk-cli`, `nested-spec-organization`

**Current overlap:**
- `spec-parser.md`: Defines core parsing logic and JSON output
- `spekk-cli.md`: Defines CLI commands (`spekk`, `spekk next`, `spekk status`) that wrap parser
- `parser-supports-nested-folders.md`: Extends parser functionality

**Recommendation:** These could merge into a single "Parser and CLI" specification since CLI commands are thin wrappers around parser functionality.

### 2. Display Formatting Duplication
**Affected specs:** `simplified-display-formatting`, `spec-explorer-web-interface`

**Current overlap:**
- Both define identical formatting patterns: `{priority} {status_icon} {title}`
- Both specify status icons and priority badge behavior
- Web interface implements same display rules as console interface

**Recommendation:** Create single "Display Formatting Standards" spec that both console and web interfaces implement.

### 3. Parser Validation Fragmentation
**Affected assertions:** 4 separate validation assertions in `spec-parser`

**Current fragmentation:**
- `validates-required-fields.md`
- `validates-status-values.md` 
- `validates-timestamps.md`
- `detects-duplicate-ids.md`

All target same parser validation functionality with similar error handling patterns.

**Recommendation:** Consolidate into 1-2 broader validation assertions instead of 4 granular ones.

## Evidence
- Parser and CLI specs both define overlapping functionality (parsing + command interface)
- Display formatting rules duplicated across console and web specs  
- Four validation assertions could be covered by comprehensive validation requirement
- Multiple specs reference same system components with different perspectives

## Impact
Having fragmented specifications creates:
- Increased maintenance overhead (updating multiple specs for related changes)
- Risk of specs diverging over time
- Higher cognitive load for developers understanding the system
- Potential for inconsistent implementation across similar components

## Recommendation
**Consolidate related specs systematically:**
1. **Merge parser + CLI**: Combine into unified "Parser and CLI Interface" spec
2. **Unify display formatting**: Single spec for formatting standards used by both interfaces
3. **Consolidate validation**: Replace 4 validation assertions with 1-2 comprehensive ones
4. **Establish consolidation guidelines**: Create standards for when specs should be merged vs. separated

This would reduce spec count while maintaining clear requirements and improving system comprehension.
