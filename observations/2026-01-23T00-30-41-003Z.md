# Multiple specs address overlapping test organization concerns

## Issue Description
Two separate specs define test organization requirements with significant overlap and could be consolidated into a single comprehensive testing standard.

## Overlapping Specifications

**test-file-organization spec:**
- Defines test file organization: `src/parser/__tests__/`
- Specifies test file naming and structure
- Requires focused, single-responsibility test files
- Has 6 sub-assertions for creating specific test files

**assertions-have-tests spec:**
- Defines test requirements for assertions
- Specifies test locations: `app/**/__tests__/` AND `src/**/__tests__/`
- Establishes test frameworks and validation protocols
- Covers both implementation tests and sidecar tests

## Evidence of Overlap
1. **Both define test file locations** (with conflicting paths)
2. **Both establish test organization standards**
3. **Both require specific test file structures**
4. **test-file-organization** has 6 granular assertions that could be covered by the broader testing standard
5. **assertions-have-tests** is more comprehensive but conflicts on directory structure

## Impact
Having separate specs creates:
- Conflicting requirements for test file locations
- Duplication of test organization rules
- Increased complexity for developers to understand testing standards
- Risk of specs diverging over time

## Recommendation
**Consolidate into single comprehensive testing spec:**
1. Merge requirements into one "Testing Standards" specification
2. Resolve directory path conflicts (`app/` vs `src/`)
3. Include both granular test file creation AND general testing protocols
4. Combine the 6 test-file-organization assertions into the broader testing standard
5. Create unified testing documentation that covers all testing concerns
