# Contradictory requirements for test file locations

## Issue Description
Two specs define mutually exclusive requirements for where test files should be located, creating an impossible-to-satisfy conflict.

## Conflicting Specifications

**no-implementation-outside-app (line 13):**
```
All implementation code lives under the `src/` directory.
```
Shows directory structure with tests in `src/**/__tests__/`:
```
src/
├── parser/
│   ├── index.js     # Core logic
│   ├── cli.js       # CLI interface  
│   └── __tests__/   # Tests (optional)
```

**assertions-have-tests (line 59):**
```  
Location: `app/**/__tests__/`
```
Shows directory structure with tests in `app/`:
```
app/
├── parser/
│   ├── index.js
│   └── __tests__/
│       ├── parser.test.js
│       └── ...
```

## Evidence
Both specs are marked with high priority and define incompatible requirements:
- One requires ALL code (including tests) in `src/`
- Other requires test files specifically in `app/`
- These cannot both be satisfied simultaneously

## Impact
**BLOCKING CONFLICT**: This conflict prevents implementation progress. Developers cannot satisfy both specs simultaneously, leading to:
- Impossible compliance requirements
- Confusion about correct project structure  
- Implementation paralysis
- Inconsistent file organization

## Recommendation
**Immediate resolution required:**
1. Review project architecture decisions about `app/` vs `src/` directories
2. Determine single source of truth for directory structure
3. Update one or both specs to align on unified structure
4. Consider if both directories serve different purposes (implementation vs validation)
5. Establish clear hierarchy if both are needed
