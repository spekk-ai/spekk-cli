# Actionable Documentation Gaps in Existing Docs Site

## Issue Description

While the existing `docs/` site is comprehensive, several areas have gaps that could benefit engineering users. These are concrete improvements to the single existing site, not justification for separate sites.

## Evidence

### Gap 1: No Architecture Documentation
The `internal/` directory contains 9 packages but none are documented beyond code comments:

| Package | Purpose | Documented in docs/? |
|---------|---------|---------------------|
| `internal/parser/` | Spec parsing, priority algorithm, JSON output | Partially (concepts.md covers behavior, not internals) |
| `internal/agent/` | Agent launchers (coach, builder, observer, loops) | No |
| `internal/cli/` | Flag parsing, prompt resolution, skill resolution | No |
| `internal/show/` | HTML generation, watch mode, SSE | No |
| `internal/serve/` | WebSocket server for browser extension | Minimal (cli-reference.md) |
| `internal/sandbox/` | DigitalOcean API, droplet management | Minimal (cli-reference.md) |
| `internal/status/` | Status overview display | No |
| `internal/version/` | Version management | No |
| `internal/update/` | Self-update mechanism | No |

### Gap 2: Observer Agent Underdocumented
The `cli-reference.md` documents `spekk observer` with only 3 lines and 2 flags. Compare this to the builder (26 lines, 7 flags, workflow explanation, lean testing philosophy callout) and coach (46 lines, 3 subcommands, detailed workflow for each). The observer is a first-class agent but gets minimal documentation.

Relevant: `specs/observer-agent/` has 10 assertions defining observer behavior, but `docs/cli-reference.md` lines 196-213 give it only a brief mention.

### Gap 3: CONTRIBUTING.md Not in Zensical Site
`CONTRIBUTING.md` (84 lines) contains development setup, versioning policy, publishing workflow, and project structure — but it's only available as a GitHub file, not in the Zensical docs site. The `docs/` navigation (`zensical.toml` lines 47-63) has no "Contributing" entry.

### Gap 4: No Troubleshooting or FAQ Page
Common issues are not documented anywhere:
- What happens when Claude CLI is not installed?
- What if `spekk next` returns empty but specs exist? (branch filtering)
- How to debug `spekk serve` connection issues?
- How to handle `go.mod` dependency issues (the current `go.mod` has a diagnostic warning about `gorilla/websocket` being indirect)?
- Self-update requires `GH_SPEKK_TOKEN` but this is only mentioned in `spekk update --help`, not in docs

### Gap 5: Sandbox Documentation Assumes DigitalOcean Knowledge
`cli-reference.md` documents sandbox commands but doesn't explain prerequisites (DO account, API token setup, VPC concepts). The `configuration.md` lists env vars but doesn't explain how to obtain them.

### Gap 6: No Update Command in Docs Site
`spekk update` (self-update) is documented in `README.md` and `cli-reference.md` mentions it's available, but there's no "Updating Spekk" section in `getting-started.md` beyond "Download the latest release binary again." The self-update mechanism (`spekk update`, `spekk update --check`, `GH_SPEKK_TOKEN` requirement) deserves proper documentation.

## Impact

- New contributors must read source code to understand internal architecture
- Observer agent adoption is limited by thin documentation
- Contributing guidelines are less discoverable outside GitHub
- Users encountering common issues have no self-service troubleshooting resource
- Sandbox feature has a steep learning curve due to undocumented prerequisites

## Recommendation

Add these pages/sections to the existing `docs/` Zensical site:

1. **`docs/architecture.md`** — Internal package overview with a Mermaid diagram showing how `main.go` routes to packages, data flow from specs to JSON output, agent launch sequence
2. **Expand `cli-reference.md` observer section** — Document drift detection types, observation format, skill activation, and how observer output feeds back into the coach
3. **`docs/contributing.md`** — Migrate `CONTRIBUTING.md` content into the Zensical site and add to `zensical.toml` navigation
4. **`docs/troubleshooting.md`** — FAQ covering common issues (branch filtering, Claude CLI dependency, self-update token, etc.)
5. **Expand sandbox section** — Add prerequisites subsection explaining DO account setup and token generation
6. **Add `spekk update` to getting-started.md** — Document self-update workflow with `GH_SPEKK_TOKEN` requirement
